Why Context Matters

How Copilot uses open files, tabs, and workspace to generate suggestions

How Copilot Gathers Context

Current File

Code above & below cursor

→

Open Tabs

Neighboring files & imports

→

Workspace Index

Semantic search of all files

→

Chat History

Prior conversation context

→

Instructions

Custom & repo-level rules

Context Quality = Suggestion Quality

Copilot can only suggest based on what it sees. Vague function names, no comments, and closed relevant files all reduce suggestion quality. Garbage in, garbage out.

Context Priority Order

  • 1. Selected / highlighted code
  • 2. Current active file content
  • 3. Open editor tabs
  • 4. Workspace semantic index
  • 5. Custom instructions files

Context Sources — What Copilot Actually Reads

Inline Completions

Current file + open tabs.
Code above/below cursor weighted highest.

Copilot Chat

Chat history + referenced files via #file + selected code.

Agent Mode

Full workspace via semantic search, grep, file reads, usages, and terminal output.

Key Insight

Agent mode has access to significantly more context than inline completions. For complex tasks, switch from inline completions to Chat or Agent mode to give Copilot the full picture of your codebase.

Context Setting Techniques

Relevant file ordering, pinning files, and using comments as anchors

Context Optimization Strategies

Pin Key Files

Keep architecture docs, interfaces, and config files pinned in editor tabs

Order Tabs by Relevance

Open related files before prompting — close irrelevant ones to reduce noise

Use Comments as Anchors

Write intent comments before code — they're Copilot's strongest signal

Select Before Asking

Highlight specific code snippets, then ask Chat — more precise than entire files

Use Exact Code Terms

Reference actual class/function names like PaymentService, not "payment module"

Close Irrelevant Files

Too many open tabs = noisy context. Keep only what matters for your current task

Explicit Context References in VS Code

// Example: Referencing files explicitly

Pro Tip

Combine references: #file:types.ts + selected code + your question = laser-focused context for better answers.

Custom Instructions

Project-level instructions to steer Copilot responses with copilot-instructions.md

Repository-Wide Custom Instructions

# .github/copilot-instructions.md

## Repository Overview
Node.js/React app for task management.
Languages: TypeScript (75%), CSS (20%)
Frameworks: React 18, Express.js, PostgreSQL

## Coding Conventions
- Use functional components with hooks
- Prefer named exports over default
- All functions must have JSDoc comments
- Use Zod for runtime validation

## Testing
- Use Vitest + React Testing Library
- Every component needs a .test.tsx file
- Minimum 80% coverage on new code

  • File Location

    .github/copilot-instructions.md — Markdown format, auto-injected into all Copilot requests

  • What to Include

    Project overview, tech stack, coding conventions, build commands, testing standards, file structure

  • Priority Order

    Personal instructions > Org instructions > Repo instructions (highest to lowest)

Path-Specific Files

- Use strict mode for all functions
- Prefer interfaces over type aliases

Agent Instructions

  • .github/AGENTS.md

    Universal instructions for all AI agents working on your repo

# .github/AGENTS.md
- Use pnpm as the package manager
- Run pnpm test before committing
- Follow conventional commits format
- Never modify generated/ files directly

  • CLAUDE.md / GEMINI.md

    Model-specific agent instructions. Nearest file in directory tree wins.

# CLAUDE.md (project root)
- Always think step-by-step before writing code
- Use snake_case for Python, camelCase for TS
- Write unit tests for every new function
- Prefer async/await over callbacks

Which approach should you use?

Start with a single .github/copilot-instructions.md for project-wide coding standards. Add .instructions.md files when you need different rules for different file types or frameworks. Use AGENTS.md if you work with multiple AI agents in your workspace.

Prompt Engineering
Fundamentals

Zero-shot, few-shot, role-based, and chain-of-thought prompting

4 Core Prompting Strategies

Zero-Shot Prompting

Direct instruction with no examples. Works best for straightforward, well-defined tasks.

// "Generate TypeScript interfaces for a
// REST API with auth and refresh tokens"

Few-Shot Prompting

Provide input/output examples so Copilot learns the desired pattern and format.

// "findDates('meeting 11/14/23 and 12-1-23')
// → ['11/14/23', '12-1-23']"

Role-Based Prompting

Assign Copilot a persona to shape response style, depth, and focus area.

// "You are a security architect. Review
// this auth flow for vulnerabilities."

Chain-of-Thought

Break complex reasoning into explicit steps. Makes Copilot "think out loud."

// "Step 1: Identify dependencies
// Step 2: Map states → Step 3: Refactor"

Prompting Best Practices

Do This

  • Start broad, then get specific — iterate to refine
  • Give examples (input/output pairs or unit tests as specs)
  • Break complex tasks into smaller sequential steps
  • Use exact names: createUser(), not "the function"
  • Start new chat threads for different tasks
  • Keep existing code clean — Copilot mirrors your style

Avoid This

  • "What does this do?" — ambiguous: what is "this"?
  • "Use the common library" — which one exactly?
  • One giant prompt for a full feature — break it down
  • Ignoring failed results — iterate and guide instead
  • Keeping irrelevant history — clutters context window
  • Vague variable names in your code — Copilot reflects them

Golden Rule

The best prompt often isn't a prompt at all — it's well-written code with descriptive names and a leading comment. Copilot completes what you start.

Advanced Prompting

Complex refactors, design-pattern generation, test scaffolding & multi-file edits

Advanced Prompting Patterns

Test-Driven Prompting

Write tests first as your spec, then ask Copilot to generate the implementation that passes them.

Unit Tests Integration

Design Pattern Generation

Request specific patterns: Observer, Factory, Strategy — with typed interfaces and concrete examples.

GoF Patterns SOLID

Complex Refactoring

Extract modules, migrate frameworks, restructure architectures — with coordinated cross-file changes.

Monolith → Services Framework Migration

Example: Test-Driven Prompt

// "Write unit tests for a calculateMortgage function.
// Cover: valid inputs, edge cases (0 rate, 0 months),
// and invalid inputs. Use Vitest.
// Then generate the function that passes all tests."

Multi-File Edit Strategies

  • Describe the Target Architecture

    Tell Copilot the current structure and desired end state clearly

  • Reference All Affected Files

    Use #file or @workspace to include every file involved in the change

  • Ask for Coordinated Changes

    Request import/export updates, type changes, and test updates together

  • Review & Iterate

    Accept or reject file-by-file. Ask follow-ups for missed edge cases.

// Multi-file refactoring prompt

"Extract payment validation from
checkout.ts into a new PaymentValidator
service. Update OrderController and
StripeIntegration to use the new module.
Update all imports and add unit tests."

// Copilot Agent will:
// 1. Create PaymentValidator.ts
// 2. Move validation logic
// 3. Update imports in 2+ files
// 4. Create PaymentValidator.test.ts
// 5. Run tests to verify ✓

Agent Mode excels here

For multi-file edits, use Agent mode — it autonomously coordinates changes across files, runs tests, and self-corrects.

What is Agent Mode? GA

Unlike inline completions, agents take high-level goals and execute them autonomously — planning, coding, testing, and self-correcting.

Plans Before Coding

Analyzes codebase, creates implementation strategy

Edits Multiple Files

Coordinated changes across your entire project

Runs Terminal Commands

Build, test, lint — verifies its own work

→

2. Analyze Codebase

→

3. Implement & Test

→

4. Self-Correct & Verify

Built-in Agent Types in VS Code

Agent

Autonomous planning & implementation. Runs terminal commands, invokes tools.

Best for: Building features end-to-end

Plan

Creates detailed step-by-step plans. Asks clarifying questions before acting.

Best for: Complex refactors & migrations

Ask

Answers questions about code — does NOT make file changes. Read-only Q&A.

Best for: Learning & understanding

Custom PREVIEW

User-defined agents with specific roles, custom tools, and instructions.

Best for: Specialized workflows

Choosing the Right Mode

Use Ask for quick questions → Plan to strategize complex changes → Agent to execute. Start conservative, escalate when needed.

MCP is an open standard for connecting AI agents to external tools and services — databases, APIs, browsers, and more.

// User prompt:
"Open the website, test the login form,
take a screenshot of the result"

// Agent with Playwright MCP:
// 1. Opens browser via MCP tool
// 2. Navigates to login page
// 3. Fills form, clicks submit
// 4. Captures screenshot via MCP
// 5. Returns image + test results ✓

Permission Control

Agents request approval before invoking MCP tools. You control what runs: default approval (safe tools auto-run) or always confirm.

MCP — How It Works

MCP follows a client-server architecture where the AI agent acts as the client and each tool is a lightweight server.

You (Prompt)

Natural language request in Copilot Chat

→

MCP Client (Agent)

Copilot decides which tool to call & builds the request

→

MCP Server (Tool)

Executes action & returns structured results

Configuration (settings.json)

"mcp": {
  "servers": {
    "playwright": {
      "command": "npx",
      "args": ["@anthropic/mcp-playwright"]
    },
    "github": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-github"]
    }
  }
}

How the Flow Works

  • 1

    Discovery

    Agent reads MCP config and learns available tools & their capabilities

  • 2

    Tool Selection

    Agent matches your prompt to the right MCP tool automatically

  • 3

    Execute & Return

    Tool runs, returns structured data, agent incorporates into response

Build Your Own MCP Server

// Minimal MCP server (TypeScript)
import { McpServer } from "@modelcontextprotocol/sdk";

const server = new McpServer("my-tool");

server.tool("get_status",
  "Check deployment status",
  { env: z.string() },
  async ({ env }) => ({
    content: [{ type: "text", text: `Deployed to ${env}` }]
  })
);

Agentic Coding
in Practice

Agent-driven workflows, tool use, terminal commands & iterative self-correction

Three Agent Workflow Patterns

Local Agent (Interactive)

Open Chat → Select Agent mode → Type your goal → Review changes live in editor.

  • ✅ Real-time review
  • ✅ Accept/reject per file
  • ✅ Iterative guidance

Cloud Agent (PR-based)

Assign task → Agent runs remotely → Creates a pull request → Team reviews.

  • ✅ Runs asynchronously
  • ✅ Creates full PRs
  • ✅ Team-friendly workflow

Hand-off (Combined)

Plan → Local Agent prototype → Cloud Agent for production PR. Context carries over.

  • ✅ Best of both worlds
  • ✅ Prototype locally first
  • ✅ Ship via cloud PR

Semantic vs. Keyword Search

@workspace uses semantic search — it finds code by meaning, not just keywords. Asking "permission validation" finds checkAuth(), validateAccess(), and isAuthorized() even though none match the search terms.

Key Takeaways

🎯

Context is King

Better context = better suggestions. Open relevant files, write clear comments, use #file and @workspace references.

📝

Craft Your Prompts

Use zero-shot, few-shot, role-based, and chain-of-thought patterns. Be specific, give examples, iterate.

📋

Set Instructions

Create copilot-instructions.md and path-specific rules to make Copilot follow your team's conventions.

🤖

Embrace Agent Mode

For complex multi-file tasks, let agents plan, implement, test, and self-correct autonomously.

🔌

Extend with MCP

Connect agents to external tools via MCP — databases, browsers, APIs, and your own custom integrations.

🔄

Iterate & Learn

Prompting is a skill. Experiment, refine, keep chat history clean, and learn from what works best for your codebase.
