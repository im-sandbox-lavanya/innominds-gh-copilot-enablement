Repositories, Branches & Commits

Repository

The container for your project — contains all code, history, issues, and settings

  • Public or private
  • Forking for open source
  • README, LICENSE, .gitignore

Branches

Isolated lines of development that diverge from and merge back to main

  • main / develop as defaults
  • Feature branches per task
  • Branch protection rules

Commits

Snapshots of your changes — each commit has an author, message, and SHA hash

  • Atomic, purposeful changes
  • Commit messages matter
  • Blame, log, diff views

Best Practice: Commit Early, Commit Often

Small, focused commits with clear messages make code review easier and history meaningful. Use conventional commits (feat:, fix:, chore:) for consistency.

Pull Requests & Code Review

  • Pull Requests (PRs)

    Propose changes from a branch. Trigger discussion, review, CI checks before merging to main

  • Code Review

    Reviewers comment on specific lines, request changes, or approve. Required reviewers enforced by branch rules

  • Status Checks

    CI/CD pipelines must pass before merge. Enforces quality gates automatically

  • Copilot PR Summaries

    GitHub Copilot auto-generates PR descriptions and review suggestions

Branch Protection Rules

  • ✅ Require pull request reviews before merging
  • ✅ Require status checks to pass
  • ✅ Require signed commits
  • ✅ Restrict who can push to branch
  • ✅ Require linear history

GitHub Flow

1. Branch

Create a feature branch from main

2. Commit

Make commits with clear messages

3. Pull Request

Open a PR to start discussion

4. Review

Team reviews and approves

5. Deploy

Deploy from branch to verify

6. Merge

Merge to main and delete branch

GitHub Flow vs Git Flow

GitHub Flow is simpler — one main branch, short-lived feature branches. Ideal for teams deploying continuously. Git Flow adds release/hotfix branches and suits teams with scheduled releases.

GitHub Deployment
Options

GHEC, EMU, and GHES — when to use what

GitHub.com – Free & Team Plans

GitHub Free

  • Unlimited public & private repos
  • 2,000 Actions minutes/month
  • 500 MB Packages storage
  • Community support

GitHub Team — $4/user/month

  • 3,000 Actions minutes/month
  • 2 GB Packages storage
  • Required reviewers & CODEOWNERS
  • Draft pull requests

Who Is This For?

Free: Individuals, open-source projects, small personal teams with no compliance needs.


Team: Small-to-medium businesses that need collaboration features, required reviews, and more CI minutes — without enterprise compliance requirements.

Limitation

Free and Team plans share GitHub.com's multi-tenant infrastructure. Data residency, SAML SSO, and advanced audit logs require Enterprise plans.

GitHub Enterprise Cloud (GHEC)

  • Enterprise Organizations

    Centrally manage multiple organizations under a single enterprise account with unified billing and policies

  • SAML SSO & SCIM

    Integrate with your IdP (Okta, Azure AD, etc.) for single sign-on and automated user provisioning

  • Audit Log & Compliance

    Full audit log streaming to your SIEM, IP allow lists, SOC 2 Type II & ISO 27001 certified

  • 50,000 Actions Minutes

    50K hosted runner minutes/month plus GitHub-hosted runners up to 64 cores

GHEC Use Cases

  • ✅ Large enterprise with compliance requirements
  • ✅ Centralized SSO with existing IdP
  • ✅ Need GitHub.com's full ecosystem & integrations
  • ✅ Don't want to manage server infrastructure
  • ✅ Want access to all latest GitHub features first

Enterprise Managed Users (EMU)

What is EMU?

A variant of GHEC where all user accounts are fully managed by your IdP. Users cannot create personal GitHub.com accounts.

  • Corporate identity controls everything
  • Users can only see enterprise repos
  • No mixing personal & work identities

When to Choose EMU

  • ✅ Strict identity governance required
  • ✅ Regulated industries (finance, govt, healthcare)
  • ✅ No developer personal accounts allowed
  • ✅ Full offboarding control needed
  • ❌ Not for teams needing open source contribution

EMU Trade-Off

EMU users cannot contribute to public repos or interact with GitHub.com outside the enterprise. Choose EMU when isolation is more important than ecosystem openness.

GitHub Enterprise Server (GHES)

  • Self-Hosted Deployment

    Run GitHub on your own infrastructure — on-premises data centers or private cloud (AWS, Azure, GCP)

  • Air-Gapped Support

    Fully disconnected from the internet — ideal for classified or highly regulated environments

  • Data Residency Control

    All data stays within your network. You control backups, HA, disaster recovery

  • Admin & Customization

    Full admin control — custom auth, hooks, integrations, and GitHub Connect for hybrid scenarios

GHES Trade-Offs

You own the infrastructure: patching, upgrades, HA, monitoring. GHES trails GitHub.com by 3-6 months on features. Requires dedicated platform engineering resources.

GitHub Connect

Connect GHES to GitHub.com for hybrid benefits: use GitHub Actions hosted runners, access GitHub Marketplace, and enable Dependabot updates across the air gap.

Choosing the Right Deployment

GitHub.com (Free/Team)

  • Startups, SMBs
  • Open source projects
  • No compliance needs
  • Fast time-to-value

GHEC / EMU

  • Large enterprises
  • Need SSO/SCIM
  • Compliance + audit logs
  • No infra to manage

GHES

  • Air-gapped / regulated
  • Strict data residency
  • Full infra control
  • Govt / defence / finance

Hybrid Approach

Many enterprises run GHEC for most teams and GHES for specific classified or regulated workloads, connected via GitHub Connect for a unified experience.

Code Scanning, Secret Scanning, Dependabot, and Security Overview

What is GitHub Advanced Security?

  • Security Built Into the Developer Workflow

    GHAS embeds security analysis directly into GitHub — scanning happens automatically on every push and pull request

  • Find Vulnerabilities Early

    Shift security left — catch issues at code review time instead of post-deployment

  • Four Core Capabilities

    Code Scanning, Secret Scanning, Dependabot alerts, and Security Overview dashboard

Code Scanning

  • Static Application Security Testing (SAST)

    Analyzes source code for security vulnerabilities — SQL injection, XSS, buffer overflows, path traversal and more

  • Powered by CodeQL

    GitHub's semantic code analysis engine — treats code as a database and queries it for vulnerability patterns

  • Third-Party Tool Support

    Integrate any SARIF-compatible scanner (Semgrep, Snyk, Checkmarx) into GitHub's unified alerts interface

Supported Languages

C / C++ C# Go Java JavaScript TypeScript Python Ruby Swift Kotlin

PR Blocking

Configure Code Scanning to block merges when high-severity vulnerabilities are detected in a PR — enforce security gates automatically.

Secret Scanning

  • Detects Hardcoded Credentials

    Scans every commit and push for 200+ secret patterns — API keys, tokens, passwords, certificates

  • Partner Notifications

    GitHub automatically notifies service providers (AWS, Azure, Slack, Stripe) when their tokens are detected — even in public repos

  • Push Protection

    Blocks pushes containing secrets before they reach the repository — prevent exposure at the source

Secrets in Public Repos

Secret Scanning runs for FREE on all public repositories. Any secret committed is treated as compromised — rotate it immediately, even after removal from history.

Push Protection = Prevention

Enable Push Protection to block secrets before they land in any branch. Developers get an actionable error message with remediation guidance.

Dependabot

Dependabot Alerts

Notifies you when a dependency has a known CVE vulnerability. Works with npm, pip, Maven, Gradle, NuGet, RubyGems, Cargo, and more.

Dependabot Security Updates

Automatically opens PRs to bump vulnerable dependencies to a patched version — no manual intervention needed.

Dependabot Version Updates

Keeps all dependencies up-to-date on a schedule — configure per-ecosystem, per-repo, with grouping and ignore rules.

Available on Free Plans Too

Dependabot alerts and security updates are available on all plans (including Free). Dependabot version updates require at minimum GitHub Free. GHAS extends the depth of detection in private repos.

Security Overview Dashboard

  • Org-Wide Visibility

    Single pane of glass for all GHAS findings across every repository in an organization

  • Filter & Prioritize

    Filter by severity, alert type, team, or repository. Focus remediation on highest-risk issues first

  • Trend Reporting

    Track mean time to remediate, alert volume over time, and security posture improvements across teams

What You Can See

  • 📊 Total open alerts by type & severity
  • 📊 Repos with most critical alerts
  • 📊 GHAS coverage (enabled vs not)
  • 📊 Alert age and fix rate
  • 📊 Enterprise-level roll-up view

GHAS Per-Committer Licensing

  • What is a Committer?

    Any unique user who committed code to at least one GHAS-enabled private repo within the last 90 days

  • License Counting

    Licenses are consumed per unique committer — the same developer working in 10 repos counts as 1 seat

  • Partial-Month Billing

    On GHEC, GHAS is billed per active committer per month — enables gradual rollout by repository

Rolling Out GHAS Progressively

Enable GHAS on high-risk repositories first. Monitor committer count and costs. Expand to more repos as your security program matures. Use the committer dashboard in enterprise settings to track seat usage.

Example

50 developers commit to GHAS-enabled repos → 50 GHAS seats consumed. A bot that commits code also counts as 1 seat unless it's a GitHub Actions machine user exemption.

GitHub Copilot
Overview

What is Copilot, supported IDEs, and how it works under the hood

What is GitHub Copilot?

  • AI Pair Programmer

    An AI assistant built into your IDE that helps you write, understand, test, and fix code faster

  • Inline Completions

    Ghost-text suggestions appear as you type — accept with Tab, reject with Esc. Works in any language

  • Copilot Chat

    Conversational AI in your IDE. Ask questions, get explanations, generate code, fix bugs — all in natural language

  • Agent Mode

    Autonomous multi-file editing and task execution — Copilot plans, executes, and validates complex changes independently

Productivity Impact

GitHub studies show developers with Copilot complete tasks 55% faster, report higher job satisfaction, and spend more time on creative problem-solving vs. boilerplate.

55%
faster task completion
46%
less mental fatigue reported

How Copilot Works Under the Hood

1. Context Collection

Open files, cursor position, recently viewed files, comments, and repo context are gathered

2. Prompt Construction

Context is assembled into a prompt respecting the model's token limit via intelligent truncation

3. LLM Inference

Prompt is sent to GitHub's hosted models (GPT-4o, Claude, Gemini) — your code never trains the model

4. Suggestion Delivery

Completions are filtered, ranked, and displayed as inline ghost text or chat responses

Privacy & Data Handling

Copilot does NOT use your code to train AI models. With Business/Enterprise plans, prompts are not retained. Your code stays private.

Supported IDEs & Environments

Visual Studio Code

Full feature set — completions, chat, agent mode, edits, terminal assistance, and extensions

JetBrains IDEs

IntelliJ IDEA, PyCharm, WebStorm, Rider, GoLand — completions and chat

Visual Studio

Completions and Copilot Chat for C#, C++, VB.NET, and .NET development

Neovim

Inline completions via the copilot.vim plugin — full keymap customization

GitHub.com

Copilot Chat on github.com, Copilot in PRs (summaries & review suggestions), and Copilot in Issues

GitHub Mobile & CLI

Copilot in GitHub Mobile for chat and Copilot CLI for terminal command suggestions

Copilot Admin &
Policy Controls

Org-level settings, content exclusions, and managing seat assignments

Organization-Level Settings

  • Enable / Disable Copilot

    Admins can enable Copilot for all members or specific teams. Granular control at org and team levels.

  • Duplication Detection

    Block suggestions that match public code — reduce IP risk by filtering suggestions resembling open-source code

  • Chat in IDE

    Control whether Copilot Chat is available to users — enable for all, specific teams, or disable org-wide

  • Usage Metrics

    View acceptance rates, active users, languages used — accessible via API and the org's Copilot usage dashboard

Where to Find Settings

  • github.com/organizations/{org}/settings/copilot
  • → Policies tab: duplication, chat, CLI settings
  • → Access tab: seat assignments & team access
  • → Content exclusions: file/path-level filtering
  • → Usage: adoption metrics per user & team

Content Exclusions

  • What Are Content Exclusions?

    Configure Copilot to ignore specific files or paths — it won't use them as context or generate suggestions when working in them

  • Glob Pattern Syntax

    Use glob patterns to exclude files: **/secrets/**, **/*.env, src/proprietary/**

  • Scoping Options

    Set at org level (applies to all repos) or at individual repo level via .github/copilot-exclusions.yaml

Example Exclusion Config

# .github/copilot-exclusions.yaml
paths:
  - "**/secrets/**"
  - "**/.env*"
  - "**/proprietary/**"
  - "src/auth/tokens.ts"

Use Case

Exclude files containing proprietary algorithms, secrets management code, or sensitive PII data from Copilot's context window to prevent accidental exposure.

Managing Seat Assignments

Assigning Seats

Grant Copilot access to individual users or entire teams. Changes take effect immediately — no restart required.

Revoking Seats

Remove Copilot access from users who leave teams or the org. Seats are freed instantly and billing adjusts next cycle.

Inactive Seat Cleanup

Filter by "Last active" to identify unused seats. GitHub reports seats not used in 30+ days — reclaim to optimize costs.

Manage at Scale via API

Use the GitHub REST API (POST /orgs/{org}/copilot/billing/seats) to automate seat provisioning — integrate with your HR system or SCIM provider for zero-touch lifecycle management.
